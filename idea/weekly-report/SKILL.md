# Weekly Report

输出一份可直接粘贴到飞书文档的周报，以及一篇可在周会朗读的短发言稿。只使用用户提供或已读取资料中的事实，不编造结果、风险、日期或承诺。

## 收集信息

1. 确认本周日期范围；未提供时用“本周”。
2. 对每项工作收集：重点工作名称、关键进展、待改进或下一步。
3. 收集下周计划及明确的时间节点。信息缺失时标为“待补充”。
4. 用户要求沿用个人历史风格时，优先从飞书中读取近期周报；无法访问时读取 `references/examples.md`。只参考结构、语气和颗粒度，不复用旧事实。

## 周报格式

按以下结构输出，保持简洁：

```markdown
# <日期范围>

## 本周工作内容

| 重点工作 | 关键进展 | 待改进 |
| --- | --- | --- |
| <项目或事项> | 1. <已完成或关键进展>\n2. <已完成或关键进展> | <待优化、风险或下一步> |

## 下周工作计划

- [ ] <计划事项；有明确截止时间时写明>
- [ ] <计划事项>
```

- 重点工作按项目或事项归类；同一项目最多列 3 至 5 个最有价值的进展。
- “关键进展”强调完成内容、能力变化和可验证结果。
- “待改进”写尚未完成的优化、风险或下一步，不重复已完成事项。
- 下周计划写成可执行动作，优先保留项目名、交付物和截止时间。

## 简短发言稿

周报后另起一节输出“发言稿”。按重点项目分别写 1 段，每段 80 至 120 字，遵循：

1. 先说本周完成的关键改进或结果。
2. 再说其带来的价值或当前状态。
3. 最后说下一步重点；不要逐条朗读表格。
4. 使用自然、专业、可口头表达的中文，总时长控制在 1 至 2 分钟。

若本周项目超过 3 个，只选择最重要的 2 至 3 个进入发言稿，其余用一句概括。
