# 工作流规格

## 输入

- `excel_file`：必填，单个 document 文件；原始节点名为“上传人员输入底表（0903 导入区）”。
- `query`：用户自然语言请求。

## 三类分流

- `hire`：命中“新增人员、增员、招聘优化、招聘计划、待招人数、待招聘、预算结余、招聘人数、人员扩编、扩编”。
- `cost`：命中“人力成本、人工成本、成本、薪酬总额、年度总薪酬、费用合计、预算”。
- `info`：其余请求。

招聘关键词优先于成本关键词。

## 人员查询

支持 `detail`、`list`、`count`。条件操作符为 `equals`、`contains`、`gte`、`lte`、`gt`、`lt`；普通条件为 AND，明确“或”语义时使用组间 OR。字段必须来自真实 Excel 表头，值必须来自用户原话或确定性数据候选，歧义时应返回不支持。

敏感字段包括身份证件、电话号码、家庭地址、银行账户、工资、月薪、年薪、薪资、薪酬和奖金。不得把这些字段用于筛选或返回。

## 成本预算

本地引擎先从底表计算人员和预算记录，再按原模板生成五个 Excel Sheet。底表尾部空单元格会自动补齐，详细成本区间为 `AJ:CF`。

## 招聘优化

可识别预算结余、部门、待招人数、岗位、学历、人员类型、公司主体和费用类别。可覆盖的成本参数包括基本工资、补贴、社保公积金金额或比例、福利、奖金、补偿金、体检费、团建费、补充医疗、入职月份、在岗月数、绩效核算月数、绩效折扣、社保年度上涨比例和工会计提比例。

金额统一为元，比例统一为小数。用户未明确指定的金额不得猜测，应沿用底表参考值。每条 schedule 代表一名拟招聘人员；建议在岗月数为 `13 - 入职月份`，绩效核算月数应在 0 到在岗月数之间。

## 本地依赖

- Python 3.10+
- `openpyxl>=3.1,<4`
- `PyYAML>=6,<7`

原 DSL 作为只读业务逻辑资产保留。本地引擎模拟 Excel 提取器、执行八个 Python 代码节点，并用确定性 Python 规则代替两个模型节点；不访问网络，也不需要任何外部平台或 API Key。
